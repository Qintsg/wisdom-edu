# 维护说明

> 最后更新：2026-05-11

本文档用于约束项目后续维护、交接、答辩准备和部署前检查。所有维护动作应以可回滚、可验证、可审查为基本原则。

## 维护职责

- 代码维护：保持后端 Django / DRF / Channels、前端 Vue 3 / TypeScript、GraphRAG、MEFKT、LLM 和 Agent 边界清晰。
- 文档维护：接口、配置、部署、运行命令和演示流程变化后，同步根 `README.md`、`docs/README.md`、相关专题文档和 `docs/CHANGELOG.md`。
- 数据维护：PostgreSQL 负责事务数据，Neo4j 负责知识图谱，Qdrant / 本地索引用于 GraphRAG 检索；不得把职责混写到不可追溯的临时脚本中。
- 演示维护：答辩或验收前使用仓库内工具重建演示数据，并保留验证命令输出，不将生成截图、报告和本地缓存提交到版本库。

## 依赖管理

### 后端

- 后端依赖以 `backend/pyproject.toml` 与 `backend/uv.lock` 为准。
- 新增或升级依赖后在 `backend/` 执行 `uv sync`，确认锁文件变化合理后提交。
- 不再维护 `requirements.txt`；如本地工具生成该文件，应删除并保持 `.gitignore` 拦截。

### 前端

- 前端依赖以 `frontend/package.json` 与 `frontend/package-lock.json` 为准。
- 本地依赖目录 `node_modules/` 不进入版本库；清理后用 `npm install` 恢复。
- 修改前端依赖后至少执行 `npm run typecheck` 和 `npm run build`。

## 配置与密钥

- 敏感配置只放在 `backend/.env` 或部署平台环境变量中，不提交到版本库。
- 配置模板维护在 `backend/.env.example`，新增必需配置时同步说明默认值、用途和风险。
- `backend/config.ini` 只承载版本内默认值，不保存私有 API Key、数据库密码或服务器凭据。
- 前端开发代理默认指向 `http://127.0.0.1:8000`；临时联调远端后端时优先使用 `VITE_DEV_BACKEND_ORIGIN`。

## API 契约

- `docs/api.yaml` 是唯一手写 API 契约源文件。
- 旧 `docs/API.md` 不再维护；接口说明应写入 `docs/api.yaml` 或专题使用文档。
- 后端运行态 Schema 地址为 `http://127.0.0.1:8000/api/schema/`，Swagger 为 `http://127.0.0.1:8000/api/docs/`。
- API 变化后检查序列化器、视图、前端调用、回归脚本和文档是否一致。

## 数据库与迁移

- 修改 Django Model 后执行：

```bash
cd backend
uv run python manage.py makemigrations --check --dry-run
```

- 需要生成迁移时，确认迁移只包含预期字段、索引、约束或元数据变化。
- 涉及数据迁移时优先写可重复、可回滚、可解释的迁移逻辑，避免依赖临时脚本修正生产数据。
- PostgreSQL 测试库创建失败通常是环境权限问题，应在结果说明中区分环境阻塞和代码回归。

## GraphRAG、KT、LLM 与 Agent

- GraphRAG 改动应明确查询重写、检索、上下文构造、图查询增强和答案组装边界。
- KT 改动应说明输入观测、掌握度输出、兜底策略和推荐链路影响。
- LLM 改动应说明提供方、模型、超时、重试、非思考模式、JSON 解析和 fallback 策略。
- Agent 只用于多步编排和工具路由，工具集应保持最小化，不能绕过权限、审计和业务校验。

## 验证清单

### 后端

```bash
cd backend
uv run python manage.py check
uv run python manage.py makemigrations --check --dry-run
```

涉及数据、API 或演示链路时补充：

```bash
uv run python tools.py db-check
uv run python tools.py django-check
uv run python tools.py api-regression --all --json
```

### 前端

```bash
cd frontend
npm run typecheck
npm run build
```

涉及页面、路由、图谱、问答、推荐或登录态时，应补充浏览器巡检：

```bash
cd backend
uv run python tools.py browser-audit --scenario audit --frontend-url http://127.0.0.1:3000 --api-base-url http://127.0.0.1:8000
```

### 仓库清洁度

```bash
git diff --check
git status --short
```

确认 `.claude/`、`.playwright-cli/`、`.playwright-mcp`、`.pytest_cache/`、`.ruff_cache/`、`.oms/`、`node_modules/`、`requirements*.txt`、`AGENTS.md`、`AGENT_TODO.md` 与 `DESIGN.md` 不作为新增文件进入版本库。

## 发布与交接

- 每个独立工作块使用中文 Conventional Commit，例如 `docs(readme): 完善项目说明`。
- 发布或答辩前检查根 `README.md` 的项目元信息、资助声明、启动命令、文档导航和许可证是否仍准确。
- 交接时说明影响范围：API、数据库、图谱、KT、RAG、LLM、Agent、前端页面、平台配置和部署。
- 不保留临时调试脚本、一次性报告、缓存、空目录或本地依赖产物。
